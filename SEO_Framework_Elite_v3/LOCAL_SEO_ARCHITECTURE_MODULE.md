# Local SEO Architecture Module

## Purpose
This module extends the SEO framework into a scalable local SEO operating system.

---

# Core Principles

- Every location page must provide unique operational value.
- Never duplicate city pages with only location swaps.
- Reinforce geographic relevance naturally.
- Prioritize service intent over keyword stuffing.
- Use local entities, operational proof, and geographic context.

---

# Geographic Structure

## Recommended Hierarchy

### Primary Hub
- Main service page

### Supporting Local Pages
- City pages
- Regional pages
- Service-area pages

### Supporting Intent Pages
- Emergency services
- Same-day services
- Commercial services
- Industry-specific services

---

# Local SEO Requirements

## Required Elements
- Unique local introduction
- Geographic relevance
- Local terminology
- Unique FAQs
- Unique CTAs
- Original imagery
- Local proof signals
- Embedded map if applicable

---

# Duplicate Prevention Rules

DO NOT:
- Replace only city names
- Reuse identical paragraph structures
- Reuse identical headings
- Duplicate FAQs across regions

REQUIRE:
- Unique service context
- Different customer concerns
- Distinct operational references
- Unique local insights

---

# Local Conversion Rules

Every local page should include:
- Clear CTA
- Mobile-first structure
- Contact accessibility
- Trust signals
- Service availability messaging

---

# Local Schema Checklist

Recommended schema:
- LocalBusiness
- Service
- FAQPage
- BreadcrumbList
- AggregateRating
- GeoCoordinates
- AreaServed
