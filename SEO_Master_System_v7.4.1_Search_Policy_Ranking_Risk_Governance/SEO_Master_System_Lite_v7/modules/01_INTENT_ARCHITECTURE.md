# Module 01: Intent and Architecture

## Objective
Assign a clear user task and page role to each URL, map relevant topics/entities, and resolve overlap without unsupported metric claims.

## Rules
1. Separate query wording from inferred intent.
2. Assign one dominant intent, audience, funnel job, and conversion role per URL.
3. Use secondary queries only when they support the same page purpose.
4. Include entities only when they improve comprehension, trust, comparison, decision-making, or retrieval.
5. Use volume, difficulty, CPC, rankings, and competitor findings only when sourced and dated.
6. Diagnose overlap using audience, task, intent, page promise, scope, and conversion role.
7. Resolve overlap through differentiation, merge, hub-and-spoke, canonical, redirect, noindex, or retirement.
8. Recommend a new page only when it has a distinct purpose and enough unique value to justify indexation.

## Deliverable
Intent/page-role table; topic/entity map; page-query map; cannibalization matrix; architecture and internal-link recommendations.

## v7 Specialist Guidance
- Classify dominant and secondary intent before mapping page roles.
- Build an entity map covering the primary entity, supporting entities, relationships, proof assets, location, audience, and outcomes.
- Use semantic coverage and topical completeness; never use keyword-density targets.
- When competitor evidence is supplied or observed, identify missing entities, unanswered questions, and page-role gaps. Do not invent competitor findings.
