# SEO Master System v7.4.1 — Package Chooser

Select exactly one package per project/run.

| Package | Mode | Format | Use when |
|---|---|---|---|
| `SEO_Master_System_v7` | Full | Modular | Repository, API, IDE, agent, automation, formal/high-risk work |
| `SEO_Master_System_Flat_v7` | Full | Flat | Complex ChatGPT projects, regulated content, formal audits |
| `SEO_Master_System_Lite_v7` | Lite | Modular | Lower-overhead automated or repository workflows |
| `SEO_Master_System_Lite_Flat_v7` | Lite | Flat | Routine manual ChatGPT work |

## Selection rules

- Never load Full and Lite controllers together.
- Never load Flat and Modular copies of the same active system together.
- Use Full for regulated, scaled, migration, penalty/ranking-drop diagnosis, policy disputes, or client-facing audit trails.
- Use Flat when the interface cannot reliably discover folders.
- Use Modular when file discovery and paths are reliable.

## First step

Open the chosen package's `START_HERE.md`, load its sole controller and canonical context, then allow the controller to select the smallest complete module route.

## Module 09

All four editions include Module 09. Mode A handles one asset, Mode B handles related batches, and Mode C governs supplied external detector evidence. Detector scores are optional and never replace the direct audit.

## Module 10

All four editions include Module 10. It is automatically routed for publication/indexation and material search-policy/ranking-risk work, including scaled/local pages, structured data, links, affiliate/review content, third-party hosted content, migrations, redirects, ranking drops, security/manual-action issues, and recovery.

Module 10 must run before final Module 07 QA when its trigger applies.
